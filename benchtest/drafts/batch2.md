# NeMo Guardrails research table: Batch 2 draft (pinned to docs latest + GitHub v0.24.1)

## Column E: NeMo Guardrails: Input-level PII detection & masking

- **R1:** **Input-level PII detection and masking.** Scans each user message for personal or sensitive entities before the main LLM runs. Detect flows block the message; mask flows rewrite it. **[Documented]**
- **R2:** **Personal data in user prompts.** Addresses users pasting names, emails, card or ID numbers, or similar entities that would otherwise reach the LLM, logs or tools. Coverage depends on the backend and the configured entity list. **[Inferred]**
- **R3:** **User message, before the main model.** Flows `detect sensitive data on input` / `mask sensitive data on input` (Presidio), `gliner detect pii on input` / `gliner mask pii on input`, `detect pii on input` / `mask pii on input` (Private AI), and `polygraf detect pii on input` / `polygraf mask pii on input`. **[Documented]** Detect: `bot inform answer unknown` (GLiNER: `bot refuse to respond`), then `abort`. Mask: rewrites `$user_message`. **[Documented: repo v0.24.1]**
- **R4:** **Entity recognition by a local library or remote service.** Presidio analyses text with spaCy `en_core_web_lg`. GLiNER-PII, Private AI and Polygraf are HTTP calls to a configured `server_endpoint`. Masking replaces spans: GLiNER uses `[LABEL]` such as `[FIRST_NAME]`, Polygraf uses `<TYPE>`, and Presidio uses its default replace operator. **[Documented: repo v0.24.1]** Engine support: all input flows run on LLMRails and IORails; rewriting rails force sequential execution and turn off speculative generation under IORails. **[Documented]** Optional third-party backends: Presidio (open-source), GLiNER-PII NIM (NVIDIA-hosted API key or self-hosted; paid status to be verified), Private AI (paid / non-OSS service), Polygraf (licensing to be verified; not on the PII docs page) ... **[To be verified]**
- **R5:** **Block decision or rewritten message.** Detect actions return `is_blocked` (metadata `has_sensitive_data` or `has_pii`). Mask actions return `is_transform` with `transform_text["user_message"]`, plus `metadata` holding the original and masked text. If nothing changes the result is allow. **[Documented: repo v0.24.1]**
- **R6:** **User message text plus backend config.** Presidio: `rails.config.sensitive_data_detection.input.{entities, mask_token, score_threshold}`, `presidio-analyzer`, `presidio-anonymizer`, spaCy and `en_core_web_lg`. GLiNER: `rails.config.gliner` with `threshold` default 0.5 and a running endpoint. Private AI: `server_endpoint`, entities, and `PAI_API_KEY` for the cloud API. Polygraf: `server_endpoint` and `POLYGRAF_API_KEY`. **[Documented]**
- **R7:** **Minimum setup:** prompt harness, test prompts with synthetic PII of known types and clean controls, a NeMo config with one chosen backend and entity list, any backend service or model it needs, a stub main LLM, and a recorder for blocked, masked and forwarded text. **[Inferred from the documented rail position]**
- **R8:** `mask_token` is marked unused in the code so the Presidio masking text is unverified, the mask path builds the analyzer at default threshold 0.4 rather than the configured score_threshold, spaCy install steps not seen on the docs page, GLiNER-PII NIM licensing and whether it is open, Private AI and Polygraf pricing, Polygraf absent from the docs page, recall and precision per entity type and language, behaviour when a backend is unreachable (Polygraf fails closed per repo v0.24.1, others not checked), no `enable_rails_exceptions` path found in these flows
- **R9:** https://docs.nvidia.com/nemo/guardrails/configure-guardrails/guardrail-catalog/pii-detection ; https://docs.nvidia.com/nemo/guardrails/reference/rail-engine-support ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/sensitive_data_detection/flows.co ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/sensitive_data_detection/actions.py ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/gliner/flows.co ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/privateai/flows.co ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/polygraf/flows.co

## Column F: NeMo Guardrails: Output-level PII detection & masking

- **R1:** **Output-level PII detection and masking.** Scans the model's response for personal or sensitive entities before it reaches the user. Detect flows block the response; mask flows rewrite it. **[Documented]**
- **R2:** **Personal data leaking in generated text.** Addresses the LLM repeating PII from the prompt, context or training data. Coverage depends on the backend and entity list. **[Inferred]**
- **R3:** **Bot response, after the main model.** Flows `detect sensitive data on output` / `mask sensitive data on output`, `gliner detect pii on output` / `gliner mask pii on output`, `detect pii on output` / `mask pii on output`, and `polygraf detect pii on output` / `polygraf mask pii on output`. **[Documented]** Detect gives `bot inform answer unknown` (GLiNER: `bot refuse to respond`) and `abort`. Mask rewrites `$bot_message`. **[Documented: repo v0.24.1]**
- **R4:** **Same recognisers as input, applied to `$bot_message`.** Presidio (spaCy), GLiNER-PII, Private AI and Polygraf, with entities set under `...output.entities`. **[Documented]** Engine support: all output flows run on LLMRails and IORails. Under IORails a rewriting rail forces sequential execution, and output rewrites with streaming require `stream_first: false`. **[Documented]** Optional third-party backends: Presidio (open-source), GLiNER-PII NIM (API key or self-hosted; paid status to be verified), Private AI (paid / non-OSS service), Polygraf (licensing to be verified) ... **[To be verified]**
- **R5:** **Block decision or rewritten response.** Detect returns `is_blocked`. Mask returns `is_transform` with `transform_text["bot_message"]` and `metadata` (source, original, masked text). Otherwise allow. **[Documented: repo v0.24.1]**
- **R6:** **Bot response text plus backend config.** Presidio uses `rails.config.sensitive_data_detection.output.{entities, mask_token, score_threshold}`. GLiNER, Private AI and Polygraf use their own `output` entity lists plus the endpoint and API key settings described for input. **[Documented]**
- **R7:** **Minimum setup:** harness, a main LLM or scripted responses containing synthetic PII, clean controls, a NeMo output rail config with one backend, the backend service or model, and a recorder for the final user-visible text. **[Inferred from the documented rail position]**
- **R8:** Streaming behaviour of mask rails (whether PII is released before rewrite), `mask_token` unused in code, Presidio default replacement text, recall on model-generated PII, backend licensing and pricing, Polygraf docs coverage, no exception path seen in these flows
- **R9:** https://docs.nvidia.com/nemo/guardrails/configure-guardrails/guardrail-catalog/pii-detection ; https://docs.nvidia.com/nemo/guardrails/reference/rail-engine-support ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/sensitive_data_detection/flows.co ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/gliner/flows.co ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/privateai/flows.co ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/polygraf/flows.co

## Column G: NeMo Guardrails: Retrieval-level chunk filtering

- **R1:** **Retrieval-level chunk filtering.** Checks or rewrites the knowledge-base chunks retrieved for a turn before they reach the prompt. **[Documented]**
- **R2:** **Poisoned, sensitive or padded retrieved content.** Addresses PII in chunks, forbidden patterns, context-bloat padding and classifier-flagged text in RAG sources. **[Inferred]**
- **R3:** **`$relevant_chunks`, after retrieval and before generation.** Configured under `rails.retrieval.flows`. Flows found in v0.24.1: `detect/mask sensitive data on retrieval`, `gliner detect/mask pii on retrieval`, `detect/mask pii on retrieval`, `polygraf detect/mask pii on retrieval`, `regex check retrieval`, `context bloat detection on retrieval`, `hf classifier check retrieval $classifier`. **[Documented: repo v0.24.1]**
- **R4:** **Depends on the flow: PII backend, regex, bloat statistics or HF classifier.** Detect flows block and abort; regex and HF retrieval flows blank the chunks instead of blocking. **[Documented: repo v0.24.1]** Engine support: LLMRails only. IORails does not accept a `rails.retrieval` section, and a config declaring one routes to LLMRails by default. **[Documented]** Optional third-party backends: Presidio (open-source), GLiNER-PII NIM (paid status to be verified), Private AI (paid / non-OSS service), Polygraf (licensing to be verified), HF classifier (local or hosted engine; open-source locally) ... **[To be verified]**
- **R5:** **Chunks kept, rewritten, emptied or turn blocked.** Actions expose `is_blocked`, `is_transform`, `transform_text["relevant_chunks"]` and `metadata`. Block flows answer `bot inform answer unknown` or, for bloat, `bot inform retrieval bloated`. **[Documented: repo v0.24.1]**
- **R6:** **Retrieved chunks plus a knowledge base.** Needs a knowledge base or custom retrieval action filling `relevant_chunks`, `rails.retrieval.flows`, and the per-flow config of the chosen rail. **[Inferred]**
- **R7:** **Minimum setup:** small knowledge base with clean chunks and seeded bad chunks (PII, forbidden pattern, padding), NeMo config with `rails.retrieval.flows`, LLMRails, a stub or real LLM, and a log of the chunks passed to the prompt. **[Inferred from the documented rail position]**
- **R8:** Whether the HF retrieval flow is documented on the PII or agentic pages, whether regex or HF empty-chunk behaviour drops one chunk or all (code blanks the whole `relevant_chunks` string), chunk size limits, backend licensing, behaviour with custom retrievers, per-chunk versus joined checking

## Column H: NeMo Guardrails: Regex pattern blocklist (input/output)

- **R1:** **Regex pattern blocklist.** Blocks a user message or bot response that matches any configured regular expression. **[Documented]**
- **R2:** **Known forbidden strings or formats.** Addresses fixed patterns such as banned phrases, secrets formats or identifiers. It cannot catch paraphrases. **[Inferred]**
- **R3:** **User message or bot response.** Flows `regex check input` and `regex check output`. **[Documented]** A match gives `bot refuse to respond` and `abort`. `regex check retrieval` also exists and blanks matching chunks. **[Documented: repo v0.24.1]**
- **R4:** **Pattern matching, no model.** Each pattern is compiled once and tested with `search`; all matching patterns are listed in `detections`. **[Documented: repo v0.24.1]** `case_insensitive` defaults to false. The feature is built into the NeMo Guardrails library and needs no extra package, so it is not a third-party service. **[Documented]** Engine support: input and output flows run on LLMRails and IORails; retrieval is LLMRails only. **[Documented]** No third-party backends are documented. **[To be verified]**
- **R5:** **Block decision.** `is_blocked` plus metadata `is_match`, `text`, `detections` (matching patterns) and `source`. The flow does not branch on `enable_rails_exceptions`. **[Documented: repo v0.24.1]**
- **R6:** **Text plus pattern list.** `rails.config.regex_detection.{input,output,retrieval}.patterns` (list of regex strings) and `case_insensitive`. No models or keys. **[Documented]**
- **R7:** **Minimum setup:** harness, strings that match and do not match each pattern, a config with `patterns` for input and output, a stub LLM that returns scripted text, and a result recorder. **[Inferred from the documented rail position]**
- **R8:** Whether the docs page states the matching function (code uses `search`), ReDoS or regex timeout handling, flag handling beyond case, Unicode normalisation, behaviour on empty patterns or missing section (code logs and allows), and the multiline flag, per-tool regex on tool-call arguments and results (`regex check tool output`, `regex check tool input`) appears in develop-branch docs but not in v0.24.1 (the v0.24.1 manifest lists only the input, output and retrieval flows) and not on the live docs page
- **R9:** https://docs.nvidia.com/nemo/guardrails/configure-guardrails/guardrail-catalog/third-party/regex ; https://docs.nvidia.com/nemo/guardrails/reference/rail-engine-support ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/regex/flows.co ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/regex/actions.py

## Column I: NeMo Guardrails: Output-level injection detection

- **R1:** **Output-level injection detection.** Scans the bot's output for code, SQL, template or XSS injection payloads before it is passed on. **[Documented]**
- **R2:** **Exploit strings in generated output.** Addresses model output that could run as code or queries in downstream systems, mainly in agentic setups. The docs call it defense-in-depth, not a standalone control. **[Documented]**
- **R3:** **Bot message, after the main model.** Output rail flow `injection detection`. It is output only. **[Documented]**
- **R4:** **YARA rule matching.** Rules named `code`, `sqli`, `template`, `xss` ship with the library, with optional custom `yara_path` or inline `yara_rules`. `reject` blocks, `omit` strips the matched text. **[Documented]** Engine support: runs on LLMRails and IORails. **[Documented]** No third-party backends; YARA is open-source. **[To be verified]**
- **R5:** **Block, stripped text or allow.** Metadata holds `is_injection`, `text`, `detections` and `action`. On reject the flow says "I'm sorry, the desired output triggered rule(s)..." and aborts, or sends `InjectionDetectionRailException` when `enable_rails_exceptions` is true. **[Documented: repo v0.24.1]**
- **R6:** **Bot message text plus config.** `rails.config.injection_detection.{injections, action, yara_path, yara_rules}` and `rails.output.flows: [injection detection]`. Needs `yara-python` (docs: `pip install nemoguardrails[jailbreak]`). **[Documented]**
- **R7:** **Minimum setup:** harness, scripted bot outputs containing code, SQL, template and XSS payloads plus benign controls, config with the chosen injections and action, `yara-python`, and a recorder. No retrieval or input rails needed. **[Inferred from the documented rail position]**
- **R8:** A `sanitize` action is accepted by the code validation but raises NotImplementedError and the docs list only reject and omit, default action value, omit effectiveness (code says it may not be fully effective), false positives on code answers, YARA rule coverage, whether `bot say` text leaks the matched rule names
- **R9:** https://docs.nvidia.com/nemo/guardrails/configure-guardrails/guardrail-catalog/agentic-security ; https://docs.nvidia.com/nemo/guardrails/reference/rail-engine-support ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/injection_detection/flows.co ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/injection_detection/actions.py

## Column J: NeMo Guardrails: Context-bloat detection (input)

- **R1:** **Input-level context-bloat detection.** Flags oversized, padded or repetitive user messages before they reach the main LLM. **[Documented]**
- **R2:** **Context-manipulation padding.** Addresses long or repetitive input meant to bury instructions, make the model forget its system prompt, or burn the token budget. **[Documented]**
- **R3:** **User message, before the main model.** Flow `context bloat detection on input`. A retrieval variant exists. A reject says the message "appears oversized or padded" and aborts. **[Documented: repo v0.24.1]**
- **R4:** **Statistical checks, no model.** Size cap, Shannon entropy, longest single-character run and repeated n-grams, in that order **[Documented: repo v0.24.1]**. Defaults: max_chars 5000, min_entropy 3.5, max_repetition_ratio 0.4, max_run_ratio 0.1. `action` is `reject`, `truncate` or `warn`. **[Documented]** Engine support: input flow runs on LLMRails and IORails; the retrieval flow is LLMRails only. **[Documented]** No third-party backends. **[To be verified]**
- **R5:** **Block, truncated message or allow.** Metadata holds `is_bloat`, `action`, `detections`, `metrics`. Reject blocks; truncate rewrites `$user_message`; warn allows with detections recorded. **[Documented: repo v0.24.1]**
- **R6:** **User message text plus thresholds.** `rails.config.context_bloat_detection.{max_chars, min_entropy, max_repetition_ratio, max_run_ratio, action}` and `rails.input.flows`. **[Documented]** The code also reads `min_chars` and `ngram_size`. **[Documented: repo v0.24.1]**
- **R7:** **Minimum setup:** harness, test inputs of normal text, text over 5000 characters, repeated single character, repeated phrases and low-entropy filler, config with each action in turn, and a recorder of outcome and metrics. **[Inferred from the documented rail position]**
- **R8:** In code `truncate` only cuts for the size cap and rejects for entropy, run and repetition findings which the docs do not say, `min_chars` and `ngram_size` defaults not read, false positives on legitimate long pastes (logs, code), multilingual entropy, whether `warn` is visible to the caller
- **R9:** https://docs.nvidia.com/nemo/guardrails/configure-guardrails/guardrail-catalog/agentic-security ; https://docs.nvidia.com/nemo/guardrails/reference/rail-engine-support ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/context_bloat_detection/flows.co ; https://github.com/NVIDIA-NeMo/Guardrails/blob/v0.24.1/nemoguardrails/library/context_bloat_detection/actions.py

## Reviewer notes

- Known-fact check: the PII, regex and context-bloat flows in v0.24.1 do NOT branch on `enable_rails_exceptions`. They use `bot inform answer unknown` (Presidio, Private AI, Polygraf), `bot refuse to respond` (GLiNER, regex) or custom `bot say` text (context bloat), then `abort`. Only `injection detection` (and `hf classifier check input/output`) can send a RailException. The brief's blanket statement is therefore not true for batch 2.
- Mask text: the brief says masking uses labels like `[FIRST_NAME]`. In code that is GLiNER (`[LABEL]`, upper-cased). Polygraf uses `<TYPE>` and falls back to `<REDACTED>`. Presidio uses its `replace` operator (default is expected to be `<ENTITY_TYPE>`, from general knowledge, not read). `mask_token` is marked "not currently in use" in rail_config.py and its default is `*`.
- Presidio threshold: the config reference (develop branch) says the default score_threshold is 0.2 and the analyzer default in code is 0.4. `mask sensitive data` builds the analyzer without the configured threshold, so the config value looks unused for masking. Not tested.
- GLiNER: the docs describe the GLiNER-PII NIM (default model `nvidia/gliner-pii`, NGC key for local pull), not just an open model. The user's "open model" framing is not confirmed; paid status left as to be verified. Docs threshold default 0.5 matches. Code also supports `api_key_env_var`, `chunk_length`, `overlap`, `flat_ner`.
- Polygraf: present in code and in the engine-support table, absent from the PII docs page (confirmed on a second fetch, via summary). Needs `POLYGRAF_API_KEY`; it fails closed on provider errors. Commercial status unverified.
- Injection detection: docs say `reject` or `omit`; code validation also accepts `sanitize` but it raises NotImplementedError. No sanitize option works. YARA is stated as open-source from general knowledge.
- Context bloat: docs say `truncate`; code truncates only on the size cap and turns other detections into reject.
- Retrieval flow list (11 surfaces) was reconstructed from flows.co files plus the engine-support table counts: sensitive data (2), GLiNER (2), Private AI (2), Polygraf (2), regex (1), context bloat (1), HF classifier (1). The general-docs page for retrieval rails returned 404; the retrieval description comes from a search snippet, so R6 for column G is labelled [Inferred].
- Regex tool flows: `regex check tool output $argument=<field>` and `regex check tool input` exist only on the develop branch (docs community/regex.mdx, rail.py, IORails-only per the develop engine-support table). The v0.24.1 regex `rail.py` manifest lists only `regex check input`, `regex check output` and `regex check retrieval`, and the live third-party/regex page does not mention tool flows. The community/regex URL returns 404 today, so R9 keeps third-party/regex. Column H therefore stays input/output, with one R8 sentence.
- Label convention: facts read only in code at v0.24.1 are tagged [Documented: repo v0.24.1]; R8 cells are comma lists.
- Regex page says it is built into the library with no extra packages. It sits under "third-party" in the URL path but is not a third-party service. The docs do not state `re.search`; the code does.
- Engine-support rows were read via WebFetch summaries (two fetches, consistent); the IORails retrieval statement and the sequential/speculative rewriting statement were quoted by the fetch tool as sentences and should get a human second read.
- R3 and R4 in column E exceed 90 words once the engine and backend sentences are counted; trim in the spreadsheet if needed.
