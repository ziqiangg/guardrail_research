## Scope (user-decided unless marked PROVISIONAL)
- **Sensitive Data Protection (SDP)** is Google Cloud's managed service for finding and transforming sensitive data. It was formerly called Cloud DLP. The product page says: "Cloud Data Loss Prevention (Cloud DLP) is now a part of Sensitive Data Protection. The API name remains the same: Cloud Data Loss Prevention API (DLP API)." The API host (`dlp.googleapis.com`), IAM roles (`roles/dlp.admin` and `dlp.user`, named in P0; the `roles/` form of `dlp.user` and the permission set are to be re-read from the roles page) and the Python package (`google-cloud-dlp`) keep the DLP name. Mention "formerly Cloud DLP" and "DLP API" in R1 and R4 Detail of SD1; use the new name in headers and Summaries (conflict C4 is a naming note, not a contradiction).
- **It is not a guardrail with a verdict, except the content policy.** `content.inspect` returns findings (infoType, likelihood bucket, location, optional quote), and `content.deidentify` returns transformed content. Neither blocks anything; the caller decides. R5 and R7 must say so plainly. The only ALLOW or BLOCK output is the content policy (SD7, see below).
- **Header prefix (PROVISIONAL, open question Q01, fixed at CP1).** Default `Sensitive Data Protection:` (the name Google's docs, pricing page and console use). Alternative `Google Cloud Sensitive Data Protection:` (matches the CLAUDE.md product row). R009: prefix = the product's own name as its owner writes it. If CP1 changes it, only this brief's headers and the drafts' `## Column` lines change. Never write "Cloud DLP" in a header.
- **Table 3 columns (PROVISIONAL, open question Q03).** Default is six columns, SD1 to SD6. SD2 (custom detectors and rules) may be folded into SD1, and SD4 (reversible tokenisation) into SD3. Draft all six; if CP1 folds them the merger combines the Detail bullets. Do not decide.
- **Content policy, SD7 (PROVISIONAL, open question Q02).** Default: **inventory only**, marker `— (inventory only, not in Table 3)` (R011), with the content-policy row in inventory block (a) and cross-reference Detail bullets in SD1 R4 and R8. Reason: GA since 2026-08-31 and a real allow or block verdict, but the REST resource and the client library at v3.40.0 expose only create, get, list, patch and delete. No documented way to submit an arbitrary string to a policy was found (conflict C2, gap G6), so a column would fail R7 (minimum setup). Alternative: a seventh column with the provisional header below. If CP1 picks the alternative, a third drafter writes it as `sdp_cols_c.md`. Do not draft SD7 as a column now.
- **Direction (R002).** Every content method takes one `ContentItem` (string, table, bytes, conversation or batch). There is no input or output flag, endpoint, or config section. `Conversation.messages[].participantId` is a free-text identifier and `messageType` is CONTENT or CONTEXT, which is not a prompt or response flag (CONTEXT messages are read for context only and get no findings). So each function is **one undifferentiated column** with no `Input-level` or `Output-level` prefix. R3 and R6 of every column must say it applies to prompts, responses, retrieved text, tool inputs and tool outputs alike. Image columns (SD5, SD6) take image bytes, with no direction flag either.
- **Scope guide (CLAUDE.md).** Table 3 covers functions usable on prompts, responses or their data path. Storage inspection jobs, hybrid jobs, de-identification in storage, discovery and data profiles, risk analysis (k-anonymity and similar), job triggers, and PDF or Office file inspection through jobs process data unrelated to the AI conversation. They are **inventory only** (block (a)) and need no column. They are not "planned": use the R011 marker, not the planned marker (this supersedes the P0 suggestion).
- **Model Armor (R012).** Model Armor wraps SDP (basic mode with fixed infoTypes, advanced mode with an SDP inspect template and optional de-identify template). SDP columns describe the SDP API itself. Model Armor is an **integration-path row** in inventory block (d). Cross-reference the Model Armor sensitive-data columns (`Model Armor: Input-level sensitive data detection and de-identification (Sensitive Data Protection)` and the matching Output-level header, MA5 and MA6 in `modelarmor_brief.md`) in R4 or R8 only. Never copy their internals (basic and advanced configuration, result fields, limits).
- **Other cross-references (Detail bullets and inventory only; never in a Summary, R007 item 8):** `Presidio: PII detection in text (Analyzer)` and `Presidio: PII anonymisation and masking in text (Anonymizer)` (open-source analogues of SD1 and SD3; provisional headers from `presidio_brief.md`); `GovTech Sentinel: PII detection and masking (AWS Bedrock)` (managed-cloud analogue); the NeMo Guardrails PII columns E and F wrap Presidio, not SDP (not re-checked here; do not claim anything about NeMo and SDP). Gemini Enterprise content-policy attachment is an integration path, not an SDP column.
- **Out of scope for columns (variants in Detail, or inventory only):** table (record) transformations, `Conversation` and `BatchContentItem` items and secrets or API-key infoTypes are variants inside SD1 and SD3; inspection templates, de-identification templates and stored infoTypes are inventory rows; non-AI storage features as above; Model Armor's own filters (modelarmor product).
- **No other guardrail functions.** SDP does not detect prompt injection, jailbreaks, toxicity or topic drift. State in R2 that these are out of purpose (a scope statement, `[Documented]` from the overview page). The one moderation-style feature is image safety classification (SD6) and the document-category infoTypes (e.g. `DOCUMENT_TYPE/CONTEXT/OFFENSIVE`); do not call them harm filters without the page's own wording.
- **Honesty rule.** Google publishes no accuracy, precision or recall figures, no latency figures and no backing-model names for the ML-based detectors (P0 gaps G1 to G3). Re-check, then write `[Not disclosed]` and name the pages checked. Never use customer blogs or third-party tests as evidence. The docs themselves say to test: "Google recommends that you test your settings to make sure that your configuration meets your requirements." (P1 check, infoType reference.)
