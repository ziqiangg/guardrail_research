## Scope (user-decided unless marked CP1 DEFAULT)
- **Cloak** ("The Central Privacy-Preserving Toolkit", formerly enCRYPT, renamed in v2.0.0 on 20 Nov 2023) is GovTech Singapore's whole-of-government data-anonymisation service, offered as a Web UI and as APIs. It is a closed hosted service. There is **no public repo, no Hugging Face entry and no package** (P0 checked GitHub orgs `GovTechSG`, `opengovsg`, `govtech-responsibleai`, Hugging Face; the Python package is by application only).
- **It is a data-path pre-processor, not a classifier with a verdict.** It finds personal data in a text, document or CSV and transforms it (replace, redact, mask, alias, hash, encrypt). The vendor states the AI use: "Anonymise before sending to LLMs | Strip PII in real-time via API before data reaches external LLMs or other WOG products" (docs home). R1 and R5 must say that the output is a transformed text, not a score or verdict.
- **Table 3 scope (CP1 DEFAULT, open Q01):** three columns, **free-text only**: CK1 detection and anonymisation, CK2 custom entities, CK3 reversible anonymisation and decryption. Tabular anonymisation, Mock Data Generation, the offline Anonymiser package and Mirage are **inventory only** (R011 marker). Reason: they process datasets unrelated to an AI conversation (CLAUDE.md scope guide).
- **Direction (R002): no public page shows an input/output flag, so the default is undifferentiated columns.** Checked: all 75 Cloak Guide pages plus 5 developer-portal pages for "direction", "inbound", "outbound", "input_type", "is_response" (none), and the Web UI text for any prompt versus response setting (none). The API request schema is behind login, so the absence of a flag in the API is `[Not disclosed]`, not documented. What the public pages do show: the API is organised by operation, not by direction. The release notes name a "Reconstruct endpoint for FTA API" (v2.0.1, 4 Dec 2023); the Replace (Unique) page names a `/analyze` endpoint; the free-text decryption page links a "secure-internet-api-decryption-freetext" helper script. So R3 and R6 must say each column applies to prompts, responses, retrieved text and tool outputs "that reach it as a string or file" (`[Inferred]` from "string or file in" and the vendor's LLM use case), and that the one side that is naturally response-side is the restore step in CK3 (a 2023 GovTech deck shows "Anonymised Response" going back through a "Transformer Module"). If CP1 chooses (a) and the API schema later shows a direction flag, only CK3 might need an input/output split; write CK3's anonymise-side and restore-side facts as separate bullets so a split is cheap.
- **Cross-reference, do not duplicate (main's ruling on q03).** Presidio (`PD1` to `PD6`) and Sentinel's AWS PII check (`SN6` = column AF; see also the Sentinel playbook note that a Cloak integration is "coming soon") overlap with Cloak in vocabulary. Cloak's own pages reuse Presidio names and link Presidio pages, but **no GovTech page says Cloak is built on Presidio**. "Built on Presidio" therefore stays `[Inferred]`, with the premise named (entity tag names, the Encrypt page's text "Microsoft Presidio has a built-in encryption functionality", and the Entity Types page's link to Presidio's supported-entities page). Never use the SMU library page or any other third-party page (CLAUDE.md rule 1). In Cloak columns give at most one cross-reference bullet per row where it helps (R4 and R8 mainly), citing the Presidio column ("see Presidio: PII detection in text (Analyzer)") and never restating Presidio's facts. Hosted-Sentinel facts stay under `SN6` and sheet 3e.
- **Out of scope:**
  - Mirage (the sister product for synthetic and mock data, `mirage.gov.sg`): one inventory row only; not mined.
  - Tabular anonymisation internals (tagging, transformations, k-anonymity, privacy-risk and utility analysis, tabular decryption): one inventory row each at most. P0 did not read the tabular pages in full; P2 does not need to.
  - Presidio, spaCy and AWS internals: only what the Cloak pages state, plus the owners' licence pages for inventory (f) per R019, marked "not GovTech docs".

## Table 3 headers (exact) — CP1 DEFAULT, three columns

Draft file heading form: `## Column CK1: Cloak: Free-text PII detection and anonymisation`. The text after `Column CK1:` must be copied exactly into the inventory "Covered by" cells and any cross-reference.

What each column covers:
- **CK1:** the free-text anonymisation (FTA) tool: pasted text, `.docx`, `.pdf` and `.csv` input; the 20 baseline entity tags (inventory block (c)); the techniques Replace, Replace (Unique), Redact, Mask, Alias, Pseudonymise and Encrypt as a choice per entity (block (d)); the confidence level (default 0.30), the Exceptions list and per-entity Inclusion lists; the limits (20,000 characters of pasted text; file limits); output formats; the Web UI and API routes; retention and data-classification ceiling; free-text templates; the published recall claim.
- **CK2:** custom entities added by the user in FTA: the fixed list (Inclusion feature with a Custom entity, up to 500 words), the regex ("Pattern-matching based") entity, and the LLM-enabled entity (Beta, 1 per dataset or project, up to 5,000 documents, up to 8 hours, a privately hosted language model on GCC); the API-only context words and per-pattern scores; writing definitions and 3 to 5 examples; the samples (DISEASE, DATE_TIME_SPECIFIC, PERSON_NAME).
- **CK3:** consistent and reversible transformation with managed secrets: the Encrypt technique (AES-256 CBC, base64 output), Pseudonymise with a salt, the Secrets Manager (create, share, audit keys and salts; up to 10 users per share operation, 50 per secret), free-text decryption (Web UI one value at a time; API for bulk), the "Reconstruct endpoint", and the 2023 GovTech deck's mapping-table workflow around an LLM call. Tabular decryption and tabular encryption are inventory only.

**Why the header wording matters.** CK2's "(regex and LLM)" names two of the three mechanisms; fixed lists are the third (an alternative wording at CP1: `Cloak: Custom entity detection in free text (fixed list, regex and LLM)`). CK3's "(secrets and salts)" names the Secrets Manager; salts feed the irreversible Pseudonymise technique, so reversibility comes from the encryption key only. Both are main's wording; the drafter does not change them. Raise any wording change in the QUESTIONS block.
