## Scope (user-decided unless marked PROVISIONAL)
- **Presidio** is an open-source PII toolkit: an Analyzer (detects PII in text), an Anonymizer (replaces, masks, hashes or encrypts what the Analyzer found), an Image Redactor (beta), and `presidio-structured` (tables and JSON). It is **not a guardrail with a verdict**. It returns entity spans and scores, and transformed text. R5 and R7 must say so plainly.
- **Ownership (PROVISIONAL, open user question Q01, decided at CP1).** Presidio was created by Microsoft and is now moving to the independent, community-governed `data-privacy-stack` GitHub organisation. The transition page states this and says "Microsoft supports this transition". Until CP1 rules, treat `data-privacy-stack` (repo, docs, GHCR) as the official source and record both owners in R8 or R9 notes. Do not write "Microsoft" in any header.
- **Header prefix (PROVISIONAL):** `Presidio:`. It follows R009 (the product's own name as the owner writes it). CP1 fixes it; it is frozen after CP2. If CP1 changes it, only this brief's headers and the drafts' `## Column` lines change.
- **Table 3 gets 6 columns (default, PD1 to PD6).** The alternative is a merged set of 4 columns (PD3 folded into PD2, PD6 folded into PD1). This is open user question Q02; do not decide it. Draft all six; if CP1 merges them the merger combines the Detail bullets.
- **Direction (R002).** Every Presidio function receives a string (or an image, or a table). There is no input/output flag, endpoint, or config section. So each function is **one undifferentiated column**, with no `Input-level` or `Output-level` prefix. R3 and R6 must say the column applies to both prompts and responses (and to retrieved text, tool inputs and outputs on the data path). NeMo's per-direction PII rails over Presidio are separate columns on sheet 3 (NeMo Guardrails columns E and F, headers `NeMo Guardrails: Input-level PII detection & masking` and `NeMo Guardrails: Output-level PII detection & masking`). Cross-reference them in R4 or R8 and the inventory; never duplicate their content.
- **Scope guide (CLAUDE.md).** Image redaction (PD4) applies to files and images sent to or from a model, so it is in. `presidio-structured` (PD5) applies to tables and JSON on the data path (retrieved records, tool outputs), so it is in by default, but it is the weakest fit: if CP1 treats it as bulk data processing it becomes inventory only. Mention this in PD5 R3.
- **presidio-research (R010).** The evaluation toolkit is **not** an evaluation-tooling sheet and not a column. It is one row in inventory block (a), and a cited bullet in the R7 Detail of PD1 (and PD6, PD2 where it applies).
- **Out of scope for columns (inventory or R8 only):**
  - LLM-based recognizers (LangExtract: Ollama, Azure OpenAI), GLiNER, HuggingFace NER, Medical NER, Azure AI Language and Azure Health Data Services (AHDS) recognizers. They are variants inside PD1 R4, and rows in inventory block (b).
  - The AHDS surrogate operator: a variant inside PD2 R4 and a row in block (c).
  - LiteLLM proxy callback and NeMo Guardrails flows: integration paths, block (d). LiteLLM behaviour itself is not evidence; only what the Presidio site says about it.
  - Legacy V1 (gRPC, branch `V1`, `presidio-analyzer==0.95`): a legacy row in block (a) only (R007 item 3).
  - `presidio-cli`: a component row only.
  - Prompt injection, harmful-content or topic checks: Presidio does not do these. State in R2 that they are out of purpose (a scope statement, `[Documented]` from the overview page), not "undisclosed".
- **Honesty rule.** The vendor publishes no accuracy, latency or recommended-threshold figures for the default recognizers (P0 checked the home, analyzer, evaluation and FAQ pages). Re-check, then write `[Not disclosed]` and name the pages checked. Never use presidio-research notebook claims as a Presidio accuracy figure without reading them.

## The 6 Table 3 columns (exact headers)

2. `PD2` `Presidio: PII anonymisation and masking in text (Anonymizer)`
3. `PD3` `Presidio: Reversible anonymisation and deanonymisation (encrypt and decrypt)`
4. `PD4` `Presidio: PII detection and redaction in images (Image Redactor)`
5. `PD5` `Presidio: PII detection and anonymisation in structured data (tables and JSON)`

Spelling follows R009: British for ordinary words (anonymisation, deanonymisation), vendor spelling for product terms (Analyzer, Anonymizer, Image Redactor, recognizer).

What each column covers (so the two drafters do not overlap):
- **PD1:** `AnalyzerEngine.analyze` and `POST /analyze`; the recognizer families (pattern, checksum, context, NER via spaCy, Stanza or transformers, optional LLM-based and remote recognizers); `score_threshold`, `entities`, `language`, `allow_list`, `context`, `return_decision_process`; batch analysis; default config (`en_core_web_lg`, which recognizers are enabled). Not PD6's custom-recognizer authoring.
- **PD2:** `AnonymizerEngine.anonymize` and `POST /anonymize`; the one-way operators `replace`, `redact`, `hash`, `mask`, `custom`, `keep`, `surrogate_ahds`; default operator; conflict resolution of overlapping entities; batch anonymisation. Not `encrypt` and `decrypt` (PD3).
- **PD3:** `encrypt` (AES) and `decrypt`, `DeanonymizeEngine`, `POST /deanonymize`, `deanonymize_keep`, batch deanonymisation (2.2.364 release note), key handling, and what "reversible" means for referential integrity (hash salt is in PD2; stateless note). Cover the LLM round trip (mask, send to model, restore) only as far as Presidio documents it (LiteLLM page).
- **PD4:** `ImageRedactorEngine` and `POST /redact`; OCR engines (Tesseract default, Azure Document Intelligence); `DicomImageRedactorEngine` (pixel data only, metadata not scrubbed); image PII verify engines; beta status.
- **PD5:** `presidio-structured` (`StructuredEngine`, `PandasAnalysisBuilder`, `JsonAnalysisBuilder`, `StructuredAnalysis`); column and key to entity mapping; operators applied per value.
- **PD6:** `PatternRecognizer`, `EntityRecognizer` subclasses, deny lists, allow lists, per-request ad-hoc recognizers, YAML recognizer registry (`type: custom`), context words. Analogue of NeMo's regex blocklist (NeMo Guardrails column H); mention only as a cross-reference.
