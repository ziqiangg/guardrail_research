## Scope (user-decided unless marked CP1 or PROVISIONAL)
- **Model Armor** is a managed Google Cloud service that screens LLM prompts and responses. A caller (an application, a gateway or a Google Cloud service) sends text, a document or an image to a regional endpoint with a template name. Model Armor returns a per-filter verdict. In the documented flow the application calls the LLM itself, and the calling service enforces any block.
- **Table 3 gets 10 columns, MA1 to MA10 (default, CP1 Q-A).** Alternatives are recorded under "Open user questions". Do not decide; draft all ten. If CP1 merges columns, the merger combines the Detail bullets.
- **Direction (R002).** Model Armor has separate per-direction methods (`sanitizeUserPrompt` with `userPromptData`, `sanitizeModelResponse` with `modelResponseData`, and streaming variants) and the overview advises separate input and output templates. It is a wrapper with per-direction flows, so each filter is split into an `Input-level` and an `Output-level` column (R002 definition). The filters, confidence levels and result schema are identical across directions, so each pair shares most facts. Write both columns in full (no "same as MA1"). The differences to bring out are the request field, the response-side use case, what the docs show for each direction, and any response-side gap.
- **Modality columns MA9 and MA10** (documents, images) are modalities of the same sanitize calls. They are drafted as single columns whose R3 and R6 explain both directions (default; the direction question is part of CP1 Q-A).

"Whether you are deploying AI in Google Cloud or other cloud providers" (P1 matched). Sanitize page: "Note: To sanitize prompts and responses, you must use regional endpoints." (P1 matched). Endpoint form `https://modelarmor.LOCATION.rep.googleapis.com/v1/projects/PROJECT_ID/locations/LOCATION/templates/TEMPLATE_ID:sanitizeUserPrompt` (and `:sanitizeModelResponse`); bodies `{"userPromptData":{"text":...}}` and `{"modelResponseData":{"text":...}}` (P1 matched).
- Overview: "The calling service or integration point or Policy Enforcement Point (PEP) is responsible for blocking the further processing." (P1 matched; in the Inspect and block row). The API returns a verdict; blocking is the caller's job.

**Filters, thresholds, outputs**

- Malicious URLs: "scans only the first 256 URLs found in prompts and responses" (P1 matched). The overview example is that a URL embedded in a PDF can compromise downstream systems; the filter "lets you take action and prevent malicious URLs from being returned".
