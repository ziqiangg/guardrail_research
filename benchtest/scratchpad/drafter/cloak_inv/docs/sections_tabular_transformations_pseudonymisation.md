# Pseudonymisation

Pseudonymisation [de-identifies](/sections/tabular/transformations/intro-to-transformations.md) values by replacing them with cryptographically generated values (pseudonyms). The values are generated by irreversible hashing [(SHA-256)](https://en.wikipedia.org/wiki/SHA-2) with a random salt applied to prevent brute-force attacks.

>**Salt** is a random string of characters added to the original values before they are hashed. Because it makes the original record longer, it protects somewhat against [dictionary attacks](https://en.wikipedia.org/wiki/Dictionary_attack) since there are more possible values.

---

## Are the Pseudonyms Persistent?

Cloak supports irreversible and persistent pseudonyms that provide better utility by maintaining referential integrity across datasets. This means the same pseudonym values are generated to represent the same individual within and across different datasets — conditioned on using the same salt value (explained below) for the datasets.

>Cloak will also support **encryption**, which is a reversible pseudonymisation technique.
>
>Moreover, advanced methods like **[format-preserving encryption](https://en.wikipedia.org/wiki/Format-preserving_encryption)** will be added for cases where the structure or data type of the original values need to be retained.

## How Does Hashing with Salt Work?

Hashing is a function applied to a value to produce a fixed-length output known as a **hash**. The function is one-way, so the hash cannot be converted back to the original value. Similar inputs will result in the same hash.

It is not possible to go backward (from hash to original value). This makes hashing appealing as a fast solution for de-identifying [direct identifiers](/sections/tabular/tagging/sensitivity-types.md).

However, it is vulnerable to so-called **dictionary** and **rainbow attacks** which compute the hash of all possible values where there is a fixed-sized input domain (for example, an account number), uncovering the correspondence between original records and hashes.

Therefore, it is recommended to use hashing **in conjunction with salt** (stored securely). Salt is a random string added to the original record before hashing. It makes the original record longer and protects somewhat against dictionary attacks by increasing the possible values.
