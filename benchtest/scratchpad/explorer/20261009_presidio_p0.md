## 1. Function list with PROPOSED Table 3 columns
Presidio is a PII toolkit (detect + de-identify), not a guardrail with a verdict. All text functions take a string and have no input/output direction flag, so per R002 exception a single column per function is proposed, with R3/R6 explaining use on prompts and on responses. Ids use `PD` because the docs example `PR1` would collide with purplellama (see audit).

| Id | Exact header (proposed) | Function | Direction handling (R002) | Evidence |
|---|---|---|---|---|
| PD1 | `Presidio: PII detection in text (Analyzer)` | Analyzer returns entity type, span and score for PII in free text (regex, checksum, NER, context, optional LLM-based recognizers) | Single column; no direction flag; usable on prompt or response text | S2, S3, S4, S5, S9 |
| PD2 | `Presidio: PII anonymisation and masking in text (Anonymizer)` | Anonymizer applies operators (replace, redact, hash, mask, encrypt, custom, keep, surrogate_ahds) to analyzer results | Single column (same reason) | S6, S7 |
| PD3 | `Presidio: Reversible anonymisation and deanonymisation (encrypt and decrypt)` | encrypt operator plus DeanonymizeEngine decrypt; batch deanonymisation added in 2.2.364 | Single column. CP1 may fold into PD2 | S6, S8, S19 |
| PD4 | `Presidio: PII detection and redaction in images (Image Redactor, beta)` | OCR (Tesseract default) then analyzer, then fill boxes; DICOM pixel redaction variant | Not text direction; image input. Docs say beta | S10 |
| PD5 | `Presidio: PII detection and anonymisation in structured data (tables and JSON)` | presidio-structured maps columns/keys to entities, anonymises values | Single column | S11 |
| PD6 | `Presidio: Custom-recognizer detection (regex patterns, deny lists, ad-hoc recognizers)` | User-defined PatternRecognizer, deny list, allow list, per-request ad-hoc recognizers | Single column. Analogue of NeMo H (regex blocklist). CP1 may fold into PD1 | S4, S12 |

Candidate functions deliberately NOT proposed as columns (inventory or R8 only): evaluation with presidio-research (tooling, no Table 3; see Q03); LLM-based recognizers (a variant inside PD1 R4); Azure AI Language / AHDS remote recognizers (variants inside PD1, AHDS surrogate operator inside PD2); LiteLLM and NeMo integration (integration paths block); V1 legacy gRPC (legacy marker row).
