# Pseudonymisation

Pseudonymisation de-identifies values by replacing them with cryptographically generated values (pseudonyms). The values are generated by irreversible hashing [(SHA-256)](https://en.wikipedia.org/wiki/SHA-2) or [(SHA-512)](https://en.wikipedia.org/wiki/SHA-2) with a random salt applied to prevent brute-force attacks. Read more about pseudonymisation [here](/sections/tabular/transformations/pseudonymisation.md). 

>Custom **salt** values will be included in the future. 

**Are the Pseudonyms Persistent?**

Cloak supports irreversible and persistent pseudonyms that can provide better utility by maintaining referential integrity across datasets. This means that the same pseudonym values are generated to represent the same individual within and across different datasets, conditioned on using the same salt value for the datasets.

?> **Need consistent pseudonyms across datasets?** Store your salt in the [Secrets Manager](/sections/decryption/secrets-manager.md) and share it with colleagues. Using the same salt across jobs ensures the same input always produces the same pseudonym, enabling dataset linkage on pseudonymised primary keys without exposing the originals.
