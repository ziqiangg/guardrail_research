## Answer to "is Cloak usable on AI prompts/responses at all?"
Yes in intent, with a gated access model. Evidence: official docs state the use case "Anonymise before sending to LLMs" (E01), the developer portal lists "Real-time Anonymisation for AI Products ... to strip PII from user prompts in real-time before they reach external LLMs" (E05), and a GovTech-authored 2023 deck shows an API workflow "Takes in unstructured text, returns mapping table and anonymized result" for LLM prompts (E22). Constraint: access is limited to public officers, approved vendors and approved non-government entities (E06, E07, E08), and the API guide and OpenAPI spec are behind login (E09). The bench therefore cannot self-serve (see Q02). Cloak anonymises the prompt **before** the model; it is a data-path pre-processor, not an input/output classifier.

## 6. Conflicts between official sources
1. **Entity count:** "20+ baseline entity types" (E02, E20) vs "17+ entity types out of the box" (E19). The entity pages list 20 groups/types counting address sub-types as one (Name, NRIC, Email, Phone, NRP, Address, Location, Passport, Currency, Credit Card, SG bank, IBAN, IP, URL, Date and Time, UEN, Organization = 17 default types plus Exceptions and Custom). So 17 matches the entity pages, 20+ presumably counts the address sub-entities. Report both; do not pick.
2. **E19 names "dates of birth" and "vehicle plate numbers"; the guide has no such pages** (DATE_TIME only). Possibly custom-entity examples (the structured page uses a car licence plate regex as an example).
3. **Access:** playbook calls Cloak "GovTech's dedicated internal service" (E18); the Cloak docs and developer portal say it is also open to select non-government entities (E01, E07, E20). Not strictly contradictory.
4. **Pseudonymisation page** says ">Custom **salt** values will be included in the future." while release notes v2.1.4 list "Support for custom salts and user managed salts" and v2.1.0 "Added salt parameter for Pseudonymisation transformation". Stale page text.
5. **Release-notes ordering/dates are inconsistent:** `v2.2.2 (4 August 2024)` listed above `v2.2.1 (28 August 2024)`; `v2.2.0` and `v2.1.9` both 07 August 2024. The documented 2026 features are absent from the notes.
6. **FTA CSV limits history:** v2.0.3 note says "Maximum 10 columns", "100k rows * 10 columns"; the current guide says 500 MB per file. The FAQ tabular row says 100 columns. Treat the current usage guide as authoritative; note old text.
7. **Docs "Presidio-based" is not explicit in vendor docs.** Entity tags (`<PERSON>`, `EMAIL_ADDRESS`, `IBAN_CODE`, `NRP`, `CREDIT_CARD`, `IP_ADDRESS`) match Presidio names, the Encrypt page cites Presidio's encryption tutorial, and the Entity Types page links Presidio's supported-entities page. An SMU library page says explicitly it is built on Presidio, but that is not an official GovTech source and is not used (CLAUDE.md rule 1). Cloak's Presidio basis is `[Inferred]`.
8. Minor: home page "Decryption" link points to `/sections/decryption-secret-sharing/intro-to-decryption.md` (the sidebar path is `sections/decryption/intro-to-decryption.md`); Custom entity page links point to wrong relative paths. Cosmetic.
