# Q02 — Is the SDP content policy (ALLOW or BLOCK verdict) a Table 3 column?
- Product: sdp   Phase: P0   Asked by: explorer (20261009_sdp_p0.md, SD7, C2, G6)
- Context: Content policies went GA on 2026-08-31 (release notes) and return a single ALLOW or BLOCK verdict from ordered infoType rules; the overview lists "Automatically block chatbot responses or file uploads that contain sensitive information". But the REST resource (`projects.locations.contentPolicies`) and google-cloud-dlp 3.40.0 expose only create, get, list, patch and delete; the documented consumers are Gemini Enterprise connectors, file uploads and notebooks (docs.cloud.google.com/gemini/enterprise/docs/protect-sensitive-data). No documented way to submit an arbitrary prompt or response to a policy was found. Pricing and SLO for policies are not stated.
- Options: (a) Table 3 column now, with R8 recording that testability outside Gemini Enterprise is unconfirmed; (b) inventory only (block (a) row) with a note; (c) defer to P1 after a user check of whether Gemini Enterprise access is available for tests.
- Asker's recommendation: (b), upgrade to a column only if a direct evaluation path is documented or confirmed by testing. Scope-guide wise it is a guardrail verdict function, but the bench cannot call it, so a column would fail R7 (minimum setup). Decision-bearing (scope), so route to the user at CP1.
- Blocking? no (SD1 to SD6 proceed); yes for the final column count.
