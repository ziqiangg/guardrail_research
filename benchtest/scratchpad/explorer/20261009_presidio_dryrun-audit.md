## B. Things a cloud session would lack

1. Tool names and ids (see #2): the exact ToolSearch strings, Context7 ids, the HF connector id.
2. Permissions (see #3): curl variants, node, ToolSearch, Context7/HF read tools are not in ST; "choose always allow" (HP section 2) is a manual step that an unattended run cannot do.
3. Working directory: this session started in `benchtest/`, while every doc assumes the repo root. Add "cwd = repo root; if not, `cd` to the directory containing CLAUDE.md" to CM.
4. Network: HP sets Full access; the redirect to a new domain means any allowlist-based proxy would need `data-privacy-stack.github.io`, `presidio.dataprivacystack.org`, `ghcr.io` too.
5. Date and clock (see #16).
6. A text-extraction helper (see #4); `python3` absent on Windows, `node` not guaranteed in cloud.
7. GitHub MCP resolved `microsoft/presidio` through the redirect, which hid the move; cloud explorers should check `get_file_contents`/repo metadata for the canonical full name and record it.
8. No way to read the xlsx/inventory configs needed to judge row-count granularity; the explorer only had `sentinel_brief.md` as a sample. Suggest listing in GE which existing briefs to skim (`sentinel_brief.md`) so that column/block granularity is calibrated.

## C. Were the conventions clear enough without help?

- **Naming conventions (SR file naming, product slugs, kebab-case topics, YYYYMMDD):** mostly yes. Gaps: conflicting statements of the allowed output set (#5), the "session date" source (#16), and the id prefix example that collides (`PR1`, #7 and Q04). The topic name for a combined docs+code P0 note was a guess (`p0-exploration`).
- **QUESTIONS format:** yes. SR gives a clear template (Q file with Product/Phase/Asked by/Context/Options/Recommendation/Blocking). Minor: GE says the report has a QUESTIONS block "in the format of SR" but the SR format is the file format; I used the same block in the note and wrote q-files. The agent is not told which question is "decision-bearing"; HP section 4 routing explains main's side only.
- **Report format (GE 5 items):** the five-item chat report was clear; the file's structure was not (#6) and the length cap conflicts with the evidence requirement (#17).
- **Labels:** clear (DR section 3) except for HTTP/redirect facts, code YAML, release-note text and the docs pin (#10, #11).
- **Table 3 headers:** clear on the pattern but not on vendor-in-prefix, spelling, hyphenation or length (#7).
