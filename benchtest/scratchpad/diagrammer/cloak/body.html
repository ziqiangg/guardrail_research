GovTech Cloak · hosted service, approved users only

How GovTech Cloak anonymises a conversation

Cloak is a personal-data anonymisation service run by Singapore's GovTech for government agencies and selected approved outside bodies. Your app sends it text; it finds personal data such as names, NRIC numbers (Singapore's identity card numbers), addresses and phone numbers, and hands back a rewritten copy with that data replaced, masked or encrypted. Its pages describe no safe or unsafe verdict, so it rewrites text rather than judging it. This page shows what it finds, where it fits in a chat, what can be put back, and what is not public.

Cloak, NeMo, Llama Guard, Sentinel and Presidio

A closed anonymiser, not a judge or a toolkit

The five tools sit at different levels. NeMo is a framework you run that decides where checks go. Llama Guard is one model you run that gives a verdict. Sentinel is a web service run by GovTech that gives a score for each check. Presidio is an open-source toolkit you run that finds personal data and, if asked, edits it. Cloak is also GovTech's, a hosted service that finds and rewrites personal data like Presidio, but it is open only to approved users, and no way to run it yourself is documented.

How it works

Send text or a file, get a rewritten copy back

You choose which kinds of personal data to look for and what to do to each one. Cloak finds them and rewrites them in the copy it returns. It can be used by hand on its website (the "web UI") or by a program through its API, which is a web request.

2. One job: text in, rewritten text out

Web UI or API, with settings chosen for each kind of data

Good to know: Cloak says it finds data with an underlying AI model (spaCy, an open-source language-processing library, is given as an example) plus text patterns, rule-based matching and checksums, which are checks on the digits of an ID number. Which model and version it runs is not disclosed. It runs on GovTech's Government Commercial Cloud (GCC).

Behind the door

Who can use Cloak, and what is public

Cloak is not open to the public. Government users sign in directly, other bodies need approval, and the API's own documents sit behind a login.

3. Ways in, and what is behind a login

Stage 1 · Input

Anonymising what the user typed

Your app sends the user's message to Cloak before the AI model sees it, and passes on the rewritten copy. GovTech names this use itself.

4. Personal data in a message, rewritten before the AI sees it

Free-text anonymisation · input · Yes
In
You can reach Jane Tan at jane.tan@example.com.
Masked
You can reach <PERSON> at <EMAIL_ADDRESS>. (illustrative: Cloak's default Replace technique is documented to give a tag in angle brackets; not tested)

Good to know: GovTech's only accuracy claim is ">97% recall for key PIIs like Name, NRIC and Email", meaning more than 97 in 100 of those items found (recall is the share of real personal data that is found). It gives no data set, method or precision (how many flagged items were real), and these are GovTech's numbers; ours may differ. The default setup also finds fake NRICs and phone numbers that fit the format.

Input and output · Reversible anonymising

Hiding a name from the AI model, then putting it back

Most of Cloak's techniques are one-way or say nothing about undoing them. Encrypt is the one built to be reversed. It needs a key, which Cloak's Secrets Manager keeps and can share. Putting the values back is a separate step.

Good to know: shared members of a secret can use it to decrypt without seeing the key, sharing is limited to 10 other users at a time and 50 per secret, and use is logged. A model's answer has to keep the token unchanged for the restore to work; that is our reading, and whether real AI models do so is untested. Terms clause 3.4.9 lists sharing "license keys" with a third party among the things a user shall not do; the Terms do not define the term, and whether sharing a secret counts is not stated.

Input and output · Your own entity types

Teaching Cloak your own kinds of data

The built-in types do not cover things such as hospital names or car licence numbers, and can label others wrongly: GovTech's example is a hospital case number detected as a bank account number. You can add your own: a word list, a pattern, or, in beta, a description with a few examples for an AI model. Matches are rewritten like any other. An exceptions list does the opposite and stops chosen words from being found.

Stage 3 · Retrieval, partly

Anonymising documents before the AI reads them

Cloak has no retrieval-specific check. It does take files (.csv, .pdf, .docx) and pasted text, so passages in those forms can be rewritten before they reach the AI model. GovTech's playbook lists retrieved documents among the places personal data can appear.

8. Files and passages before the AI reads them

Free-text anonymisation on files · Partly

Good to know: files go through a job that ends in a download request, with an emailed password for the zip. The usage guide's times run from 1 minute for 20 rows to 4 hours for 5,000 rows in one column. No page describes retrieval itself; that a retrieved passage can be sent as pasted text is our reading.

Limitations

What Cloak does not do, or does not tell us

  • It rewrites; it does not judge. No safe or unsafe verdict is described, and nothing is blocked. Its pages cover personal data only and describe no check for harmful content, prompt attacks, topics or actions. Your app decides what to send and passes the copy on.
  • Access is gated. Government users sign in; other bodies need approval, and Terms clause 3.3 limits use outside the public sector to a purpose GovTech has agreed in writing. The API guide and specification are behind a login, so request layout, limits, speed and any input-or-output setting are not disclosed. No public code exists, and no way to run free-text anonymisation yourself is documented. A direct Sentinel integration is described only as "coming soon".
  • Benchmarking and consent clauses are recorded, not decided. Terms clause 3.4.7 lists "perform any benchmarking tests or analyses of the Service" among the things a user shall not do, clause 3.4.11 lists "provide third party access to the Service", and Schedule 2.2 says "You are not permitted to use this Service if you are not using the Service for and on behalf of your Agency." The Terms define neither "benchmarking" nor "Agency", and whether a comparison test falls under them is not stated.
  • The only accuracy figure is GovTech's claim. It is ">97% recall for key PIIs like Name, NRIC and Email", with no method, data set or precision. Detection is probabilistic, can be weaker for uncommon formats, all-caps names and formatting artefacts, and the data owner must check the output. The Terms say the service is provided "as is" and disclaim warranties of accuracy.
  • The models are not disclosed. Cloak names an underlying AI model (spaCy as an example) plus patterns and checksums, but not which model, which version, or what the AI-model custom type uses. The deployed version is not stated: the release notes stop in August 2024, and several documented features are not in them.
  • Language and format limits. Detection is tuned for Singapore. Names are covered "including ethnic names in roman characters"; other scripts and languages are not stated. Scanned PDFs, screenshots and images are not processed. By default the NRIC and phone checks do not validate numbers, and only Singapore phone numbers are checked.
  • Only Encrypt is documented as reversible, and restoring is limited. Pseudonymise is one-way and the other techniques say nothing about undoing. The web UI decrypts one value at a time. A release note names a "Reconstruct endpoint" and 2023 slides show a mapping table, but what they do now is not stated. Anything Cloak misses stays readable.
  • Its own pages disagree in places. The type count is "20+" in one place and "17+" in another; the cut-off is per kind of data on the portal but one slider in the guide; the list limit is 500 words on one page and 500 entries on another; one page says custom salts are future while the release notes list them; the Mask page reads both ways on which end is hidden; and the Encrypt page's link to Presidio's encryption tutorial returned "not found".
