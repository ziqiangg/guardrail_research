Meta Llama Guard · Llama Guard 4 and Llama Guard 3

How Llama Guard judges a conversation

Llama Guard is a single AI model from Meta that reads part of a chat and says whether it is harmful. It is a judge, not a security system: it gives a verdict, and your app decides what to do with it. This page shows how it works, where it can sit in a chat, and what it cannot do.

Llama Guard and NeMo

A judge, not a security system

NeMo Guardrails is a framework: it decides where the checkpoints go, runs the rules a developer writes, and can edit text. Llama Guard is one judge you can post at a checkpoint. The two are not rivals. NeMo can use Llama Guard as the safety model behind its input and output checks.

How it works

An instruction goes in, a one-word verdict comes out

Llama Guard is a language model that was trained for one job. Your app writes it a short instruction, and it writes back its verdict as text.

Good to know: checking the question stops more harm but also refuses more harmless questions than checking the answer does, according to Meta's Llama Guard 4 notes. Llama Guard does not look for jailbreak tricks such as "ignore your instructions"; Meta points to a separate model, Prompt Guard 2, for that.

Stage 2b · Images

Checking a photo together with its question

NeMo's page has no image checkpoint. Two Llama Guard models can read pictures: Llama Guard 4 (several images) and Llama Guard 3 11B-Vision (one image, English).

5. Image plus text

Supported: Llama Guard 4 and 3-11B-Vision · Yes
In
[photo of a stranger on a train] Who is this and where does she live?
Verdict
unsafe · S7 (privacy)

Good to know: neither model is meant for checking a picture with no text. When checking the AI's answer, the answer itself is text. In Meta's test, Llama Guard 4 caught about 4 in 10 harmful single-image cases, clearly weaker than on text.

Stages 3 and 4 · Execution and dialog

Only partly covered

Llama Guard can help at these two checkpoints, but it is not a replacement for the rules a developer writes in NeMo. In both cases it only labels; your app still has to act.

6. Checking code before it runs

Category S14, Llama Guard 3-8B and 4 only · Partly
Code
import os; os.system(":(){ :|:& };:") # floods the machine
Verdict

Good to know: Llama Guard asks "is this harmful?", not "is this sensible?". A $5,000 refund request looks harmless to it, so business limits like NeMo's diagram 8 still need a written rule. Meta also defines no standard way to show a tool request to Llama Guard, so how we present it is our own choice and needs testing.

Limitations

What Llama Guard cannot do

  • It never acts on its own. It only answers "safe" or "unsafe". Refusing, discarding and replying are all your app's job.
  • It does not catch jailbreaks or prompt injection, such as "ignore your previous instructions". Meta points to a separate model, Prompt Guard 2, for that.
  • It can be fooled on purpose. In Meta's own attack tests on the vision model, an attacker with full access to the model crafted extra text that got 72% of harmful requests judged safe.
  • It is weak where up-to-date facts matter: defamation, intellectual property and elections. Meta says these may need extra, more complex systems.
  • It sometimes flags harmless requests. Meta warns it can increase refusals of benign prompts, more so when checking questions than answers.
  • No official cut-off and few speed figures. Meta does not say what confidence score should count as unsafe, and gives a speed figure only for the small phone version.
  • No document checks, no editing or masking, and no standard format for tool requests, as shown in the scorecard above.
  • Limits differ by model. 3-11B-Vision is tuned for English with one image; 3-1B is not tuned for code abuse (S14); Meta's pages disagree on exactly which languages Llama Guard 4 covers.
