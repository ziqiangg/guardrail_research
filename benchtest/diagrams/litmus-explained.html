GovTech Litmus · hosted service, labelled proof of concept on one portal page

How GovTech Litmus tests a conversation

Litmus is a testing service run by Singapore's GovTech and available to public sector teams. You give it the address of your AI application; it sends the application hundreds of curated test prompts and scores the replies, with a pass or fail for each test. It blocks nothing and sits in no live chat. This page shows what it tests, how a run works, what GovTech does not say about it, and how it relates to Sentinel.

Litmus, NeMo, Llama Guard and Sentinel

A test run before launch, not a guard

The tools sit at different levels. NeMo is a framework you run that decides where checks go. Llama Guard is one model you run that gives a verdict. Sentinel is a web service run by GovTech that gives a score for each check. Litmus is also run by GovTech, but it is a different kind of thing: a testing service that sends prompts to your application and scores what comes back. It measures an application; it is not a safety barrier.

How it works

Register your application, then get a pass or fail for each test

Litmus runs from the outside. Your team registers the application's address and a key, picks the tests, and Litmus does the rest: it sends the prompts, collects the replies, scores them and produces a report.

Good to know: a pass does not make an app safe. The tests are a fixed set of curated prompts, and GovTech's playbook says Litmus "does not evaluate whether your system does its job well" and that "A system that refuses every request may score well on refusal-based safety tests". The test page asks for helpful answers on some tests (Medical, Financial, Legal, Geopolitics, Social Policies), so a blanket refusal would not meet those pass conditions (our reading).

Measuring · What it tests

Fourteen tests in four categories, six of them in the smaller suite

A suite is a bundle of tests you run together. Litmus's test page offers two: Baseline, with 6 tests, and Baseline+, with all 14. The page describes what a pass looks like in words only; it gives no numbers.

Good to know: Litmus publishes none of the prompts and does not say how many each test has, where they come from, which languages they use or what licence they carry. Behind the tests

What GovTech tells us, and what it does not

Litmus's documents describe the tests and the ways in. They are silent on who or what does the scoring, where the prompts come from, and how any application has scored.

4. What the pages say, and what they leave out

Dashed boxes mean not disclosed, by request or not yet available

Good to know: GovTech does not name the engine behind the tests. A sample GitHub Action from 2024 uses a route and request fields that match the web API of Moonshot, an open test tool from the AI Verify Foundation (not GovTech), so Litmus may be modelled on it. No GovTech page says so, and the hosted service may differ.

Litmus and Sentinel

The test before launch and the checks during use

GovTech presents the two as a pair. Sentinel is a web service run by GovTech that gives a score for each check, and it operates during runtime. Litmus tests the application before it goes live.

5. Litmus before launch, Sentinel in production

GovTech's playbook and one-pager · two separate products

Good to know: the playbook warns that "If guardrails sit in front of your production endpoint but not the tested one, the scores describe a system nobody uses." It is not stated whether a Sentinel-protected endpoint can be registered with Litmus, or how its blocks would be scored. Access differs too: Sentinel is for Singapore Government public officers, in closed beta, while Litmus is described as available to public sector teams.

Limitations

What Litmus does not do, or does not tell us

  • It never acts. It is a measuring tool, not a safety barrier. A good result does not make an app safe, and Litmus recommends measures but applies none.
  • Access is by onboarding. It is available to public sector teams through an interest form. One portal page labels it proof of concept, while the docs and the playbook give no maturity label. Pricing, quotas, terms of use, data handling and retention are not published, and neither is a version number or any release notes.
  • The scoring engine and judge model are not disclosed. The docs say only "automated internal evaluation". A sample Action resembles Moonshot's web API, but that is our reading, and no GovTech page confirms it.
  • No prompts, scores or results are published. The size, source, languages and licence of the test prompts are not stated, and there is no sample report, pass threshold or published Litmus score for any model or application.
  • Its own pages disagree. The docs promise a pass or fail for each test, while a playbook example prints a refusal rate per category. The playbook calls the tests refusal-based, while the test page describes other pass conditions. The pages differ on test categories, on the web address, and on the GitHub Action's name.
  • Test the system your users meet. Results describe whatever address you registered. Whether a guardrail-protected endpoint, such as one behind Sentinel, can be tested is not stated.
  • Coverage has gaps. No tests are described for fetched documents, tool calls, images, files or multi-turn chats (the request shape has a history field, but its test use is not stated), and adaptive attack generation is not described.
  • Kaleidoscope is planned, not shipped. It checks whether an application does its job well, not whether it is safe, and GovTech's docs say Litmus will support it in the upcoming months.
